## What this audit could not see

- **Salesforce-side references are blank.** The integration user cannot use the Tooling API (CustomField / FieldDefinition / MetadataComponentDependency all return INVALID_TYPE — no View Setup). Flows, formula fields, validation rules, page layouts, reports and email templates that use a field are therefore not in this audit — run **Setup → field → "Where is this used?"** on every A and B field before deleting. Deleting a field that a Flow or formula uses is blocked by Salesforce, so the risk is a failed delete, not silent breakage; reports and list views are NOT blocked and simply lose the column.
- **Created date is blank** for the same reason. `metadata_last_modified` in the CSV is FieldDefinition.LastModifiedDate (regular API) — when the field's definition last changed.
- **"Last touched" is the record's LastModifiedDate**, not the field's — a record edited for any reason counts, so a field can be staler than it looks. The earliest "last touched" of any field with data is **2026-08-25**: the Solar records were written by the Sunbase migration, so the "≤ 5 records, untouched in 12 months" rule cannot fire yet — in practice A means no data at all.
- **Saved reports** (`public.sundial_reports`, R1b) can name a cache column. Before regenerating the report catalog after a delete, check no saved report uses the dropped column.
- Code references are token matches of the API name (and of the cache column name, marked `(col)`, when it has an underscore) across both repos' lambdas/ lib/ scripts/ sql/ src/ docs/. A `(col)` hit can be an unrelated variable of the same name.

## How the buckets were decided

- **Data:** "empty" = no record holds a value (booleans: none ticked), or ≤ 5 records none of which was modified after 2025-11-04.
- **Blocking references:** code/config files (both repos), the three xlsx sheets (the Fields-by-Section and Dealer sheets generate the portal's page configs), and Salesforce dependencies when visible.
- **Not blocking (listed as `auto_refs` / `doc_refs`):** the cache sync (describe-driven: a deleted field simply stops being selected), the generated report catalog / report-column SQL / `reporting-cache-coverage.md`, the generated access manifest `lib/field-manifest/*.json`, and prose `.md` docs. After deleting, re-run the generators (catalog, field configs) and drop the cache column if you want the column gone too.
- **A** needs empty + no blocking reference + not formula / lookup / required / external id. **B** is empty but has one of those. **C** is everything holding data. Tim's forced 12 go to A or B regardless of data.
